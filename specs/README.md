# specs/

Per-feature specifications. One file per feature: `specs/<feature>.md`.

Each spec is **self-contained**: it names the files/interfaces involved, states what is
**out of scope**, and ends with an **end-to-end verification step** the owner can judge.

Produce a spec via the `spec-interview` skill (or the template in the top-level `SPEC.md`)
in its own session, then build it in a **fresh** session containing only the distilled spec.
